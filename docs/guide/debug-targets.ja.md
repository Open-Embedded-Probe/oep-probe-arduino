# デバッグの対応ターゲット

[English](debug-targets.md)

OEP のプローブがデバッグでつなげる相手と、相手ごとに必要な配線と設定をまとめます。使い方の流れは
[OEP でできること](use-cases.ja.md#1-ch32-に書き込むデバッグする) にあります。

## 線の種類

| 線 | interface | 相手 | 本数 | PC の道具 |
|---|---|---|---|---|
| RVSWD | `oep.wire.rvswd` | WCH の RISC-V（CH32 の 2 線の系列） | 2 本（SWDIO、SWCLK） | ch32rv、ArduinoCore-CH32RV、`oep_client.riscv` |
| SWIO | `oep.wire.swio` | WCH の RISC-V（CH32V00x などの 1 線の系列） | 1 本（SWIO） | ch32rv、ArduinoCore-CH32RV、`oep_client.riscv` |
| SWD | `oep.wire.swd` | ARM Cortex-M（ADIv5 の MEM-AP） | 2 本（SWDIO、SWCLK） | `oep_client.arm` |

どの線を持つかはプローブのボードで決まります（[ボード](boards.ja.md#チップごとにできること)）。どの線も、プローブの出している
ピンのどれにでも割り当てられます。

## WCH の RISC-V（CH32）

デバッグの線の上では、RISC-V 標準の debug module を使います。止める、動かす、1 命令ずつ進める、メモリとレジスタの読み書き、
debug module 経由のログ（`sdi`、`dmdata`、`dmseq`）ができます。書き込み（flash）は ch32rv が受け持ち、どの系列も同じ RAM loader で
書きます。系列ごとの書き込みの確認状況は ArduinoCore-CH32RV の
[書き込み経路](https://github.com/ch32-riscv-ug/ArduinoCore-CH32RV/blob/main/docs/upload-routes.ja.md#系列ごとの対応) が正本です。

### 系列ごとの配線と設定

| 系列 | 線 | デバッグのピン | リセット（NRST） | 線の休ませ方・速さ | 相手ごとの注意 |
|---|---|---|---|---|---|
| CH32V002 / V003 / V004 | SWIO | PD1 | PD7。出荷時は無効（option bytes の RST_MODE が 11） | プローブが決める | NRST を使うかは、書き込むアプリが option bytes で決めます。無効のままなら、リセットはデバッグの線から行います |
| CH32V005 / V006 / V007、CH32M007 | SWIO（RVSWD にも対応するが、OEP では SWIO を使う） | PD1（RVSWD なら PD1 / PB3） | パッケージで違う（PA7、PC5、PD7 など）。出荷時は無効 | プローブが決める | チップの ID からはパッケージが分からないので、リセットの端子は基板の資料で確かめます |
| CH32X033 / X035 | RVSWD | PC18（SWDIO）、PC19（SWCLK） | PA21。option bytes の RST_MODE で有効にしたときだけ | SWCLK は high で休ませる（low では答えない）。プローブが相手から選ぶ | パッケージによって PC16 / PC11、PC17 / PC10 が 1 本の端子にまとまっています |
| CH32L103 / M103 | RVSWD | PA13、PA14 | 専用の NRST 端子 | SWCLK は low で休ませる（high のまま置くとデバッグの接続が切れる）。速さは 1 MHz まで | 72 / 96 MHz で動いている間はつながらないことがあります。試すときは、アプリの起動に待ちを入れます（ArduinoCore-CH32RV の「起動待ち」） |
| CH32V103 | RVSWD | PA13、PA14 | 専用の NRST 端子 | プローブが決める | V103 だけは長い形のフレームで話します。プローブが自動で見分けます。BOOT0 / BOOT1 は工場の ISP に入るときに使います |
| CH32V203 / V208、CH32V303 / V305 / V307 / V317 | RVSWD | PA13、PA14 | 専用の NRST 端子 | プローブが決める | BOOT0 は工場の ISP に入るときに使います |
| CH32V205、CH32V407 / V467、CH32X305 / X315 | RVSWD（1 線にも対応） | PA13、PA14 | 専用の NRST 端子 | プローブが決める | OEP で 1 線を使うには、プローブの側を SWIO だけにします |
| CH32M030 | RVSWD（1 線にも対応） | PA3（SWDIO）、PA2（SWCLK） | 基板の資料で確かめる | プローブが決める | 同上 |

- 表に無い系列は、ch32rv の対応表（`ch32rv db`、`ch32rv capabilities`）で確かめます。
- 「プローブが決める」は、線の休ませ方（SWCLK を high で休ませるか low で休ませるか）を、プローブが相手の答えから選ぶという意味です。
  決まった相手で固定したいときは、口の設定 `channel.{}.rest` で決めます（[設定項目](settings.ja.md#デバッグの線)）。
- 速さの上限は、道具が接続のたびに指定します（`max_speed`）。プローブは、その上限の中で確実に通る速さを選びます。

### リセット

デバッグの線からのリセット（OEP の `oep.target.riscv-dm` の reset、`oep_client.riscv` の `reset`）はシステムリセットです。
CPU だけでなく周辺も初期値に戻るので、書き込み直したアプリが前のアプリの周辺の設定（タイマ、割り込み、UART など）を
引き継ぎません。

- CH32 では PFIC のシステムリセットを使います。NRST の線は使いません。
- 止めて行うリセットでは、リセット後の最初の命令で止まります。
- プローブはこのために相手の RAM の先頭 16 バイトを一時的に使い、終わったら元に戻します。
- NRST の線でリセットしたいときは、attach の reset（リセットをかけながらつなぐ）を使います。

### 配線のこつ

- **NRST をつなぐ**: アプリがデバッグの端子を GPIO にしてしまったときや、深いスリープで答えないときの復旧に使います
  （`ch32rv recover --method nrst`）。NRST が option bytes で無効の系列では、アプリが有効にしている間だけ効きます。
- **BOOT0 をつなぐときは、空きの状態を決める**: プローブは使っていないピンを Hi-Z（引きなし）にします。BOOT0 を基板のジャンパで
  固定せずにプローブへつなぐなら、そのピンに `channel.{}.idle` を `pull-down`（または `low`）と設定し、ふだんは low に保ちます。
  ISP の試験をしないなら、ジャンパで GND に固定したままのほうが確実です。
- **線は短く**: 長い線や、同じ線をいくつにも分けた配線は、デバッグの線の誤動作のもとになります。同じ信号を 2 本のピンにつないだときは、
  片方を `channel.{}.disable` にします。
- **口の名前を付ける**: `oep pins --wire rvswd --name <口> --save`（1 線なら `--wire swio`）で、線をスキャンして見つけ、ラベルにします。
  スキャンは空いているピンに信号を出すので、ほかの機器をつないだピンは `--exclude` で外します。

### 止まったときの戻し方

- デバッグの線が答えない: アプリがデバッグの端子を別の用途にしていないか、深いスリープに入っていないかを疑い、NRST で戻します。
- CH32V103 が、すべての要求にステータスの誤りを返し続ける: V103 は、動いている間に短い形のフレームを受けたり、線を放されたり、
  フレームの途中で線が切れたりすると、この状態になり、電源を切るまで戻りません。相手の電源を入れ直します。OEP のプローブは、
  長い形から問い合わせ、閉じた後も線を駆動したまま保つので、ふだんの使い方ではこの状態になりません。

## ARM Cortex-M（SWD）

SWD で DP と MEM-AP を使い、メモリと周辺レジスタの読み書き、コアの停止と再開、レジスタの読み書き、相手の RAM に置いた関数の
呼び出し、システムリセットができます。Python の `oep_client.arm`（`SwdWire`、`ArmAdi`、`MemAp`、`CortexM`）から使います。

| 項目 | 内容 |
|---|---|
| 配線 | SWDIO、SWCLK、GND。必要なら NRST |
| マルチドロップの相手 | attach で TARGETSEL を指定します |
| 書き込み | flash loader は用意していません。相手の flash の手順を Python から行います |
| GDB | 用意していません |

## プローブの側の設定のまとめ

デバッグのために、プローブ本体に設定するもの（保存すれば起動のたびに効きます）:

| 設定 | 目的 | 要るとき |
|---|---|---|
| `channel.{}.label`（`<口>.swdio`、`.swclk`、`.swio`、`.nrst`） | 口の名前で相手を指す | 繰り返し使う相手。IDE のポートの一覧にも口ごとに出ます |
| `channel.{}.rest`（`oep.wire.rvswd` の項目） | SWCLK の休ませ方を口ごとに固定する | プローブの選び方に任せられない相手だけ |
| `channel.{}.hold`（各 wire の項目） | 閉じた後も線を駆動したまま保つか | 既定は保つ。線を放したい治具だけ false |
| `channel.{}.idle` | BOOT0 などを空きの間も決まった状態に保つ | プローブにつないだ BOOT 系の端子 |
| `passthrough.{}.*`（`oep.target.console` の項目） | debug module のログをシリアルポートへ流す | 普通のシリアルモニタでログを見たいとき |

接続のたびに道具が指定するもの（本体設定ではありません）: 線の種類、どのピンの組か、速さの上限、止めてつなぐか、
リセットをかけながらつなぐか。
