# 設定項目

[English](settings.md)

OEP のプローブを使うときに決めることを、どこに残るかと、何のためかで整理します。使い方ごとの流れは
[OEP でできること](use-cases.ja.md) にあります。

## 決めることの 4 つの種類

| 種類 | 例 | どこに残るか | いつ決めるか |
|---|---|---|---|
| **本体設定** | ピンのラベル、空きの状態、使用禁止、ログの素通し、Wi-Fi | プローブの中（保存すれば起動のたびに効く） | 治具を組んだとき、据え置くとき |
| **メモ** | 口の先の相手の型番、配線のメモ | プローブのメモ欄（`oep.probe.memo`） | 記録として残したいとき |
| **操作の条件** | UART の baud、I2C のアドレス、SPI の mode、デバッグの速さの上限、キャプチャの速さとトリガ | 残らない（操作のたびに道具が渡す） | 操作を始めるとき |
| **ピンの割り当て** | どの機能がどのピンを使うか | 残らない（セッションの間だけ） | 操作を始めるとき。セッションが終われば解放される |

本体設定にするのは、セッションと関係なく効いてほしいもの（待機の状態、素通し）と、どの PC・どの道具からも同じであってほしいもの
（配線の名前）だけです。通信の速さやアドレスのように、操作ごとに変わるものは本体設定にしません。

## 本体設定の扱い

```sh
oep settings items <プローブ>                 # このプローブが持つ項目、形、選択肢
oep settings show <プローブ>                  # 今の値と保存の状態
oep settings set <プローブ> core channel.GPIO2.label=mcu.swdio channel.GPIO3.label=mcu.swclk
oep settings set <プローブ> core channel.GPIO5.idle=pull-down --save
oep settings unset <プローブ> core channel.GPIO5.idle
oep settings save <プローブ>                  # 今の値を全部保存する
oep settings export <プローブ> jig.oep-settings.json
oep settings import <プローブ> jig.oep-settings.json   # 変わるところを先に見せる
```

- **set はすぐ効き、save で残る**: set した値はその場で効きます。save するまでは、再起動で消えます。save は、その時の値を全部保存します。
- **カテゴリ**: プローブ全体の項目は `core`、interface の項目はその interface の名前（`oep.wire.rvswd`、`oep.fixture.uart/0` など）で指します。
- **持つ項目はプローブで違う**: `oep settings items` に出る項目だけが使えます。Wi-Fi の無いプローブに Wi-Fi の項目はありません。
  保存の場所が無いプローブ（CH32 のプローブ）は、set した値が再起動で消えます。
- **控え**: firmware を更新する前や、別の個体に同じ治具を作るときは、export したファイルを import します。秘密の値（Wi-Fi の
  パスフレーズ）は書き出されないので、import の後に入れ直します。

## ピンのラベル（口と線の名前）

| 項目 | カテゴリ | 値 | 目的 |
|---|---|---|---|
| `channel.<ピン>.label` | `core` | 文字（32 文字まで） | ピンに名前を付ける。`口.線@相手のピン` の形なら口の名前になる |

- **形**: `S.N@P`。`S` は口の名前（英字で始まり、英字・数字・`-` の 16 文字まで）、`N` は線の名前、`P` は相手のピン（`pa13` など）。
  `@P` は省けます。役目の無い線は `S@P` と書きます。例: `mcu.swdio@pa13`、`mcu.rx@pa9`、`mcu.nrst`、`mcu@pb6`。
- **線の名前の慣行**: `swdio`、`swclk`（2 線のデバッグ）、`swio`（1 線のデバッグ）、`rx`（プローブが受ける。相手の TX につなぐ）、
  `tx`（プローブが送る）、`nrst`（相手のリセット）、`power_hi`、`power_lo`。
- **使われ方**: `oep://<プローブ>/<口>` のアドレス、IDE のポートの一覧（口ごと）、WireSkein のチャネルの指定（`mcu.swdio`）、
  テストのコードが線を名前で探すとき。プローブ自身は、ラベルでピンを動かしません。
- **大小文字**: 区別せずに一意です。表示は書いたとおりです。
- 形に合わないラベル（`LED` など）も付けられます。ピンの呼び名として使え、口にはなりません。

## ピンの空きの状態と使用禁止

| 項目 | カテゴリ | 値 | 目的 |
|---|---|---|---|
| `channel.<ピン>.idle` | `core` | `hi-z`、`pull-up`、`pull-down`、`low`、`high` | どの機能も使っていない間のピンの状態。値が無ければ Hi-Z（引きなし） |
| `channel.<ピン>.disable` | `core` | 真偽 | そのピンをどの機能にも使わせない。プローブは触らない |

- **idle を使う場面**: 相手の入力を浮かせたくない線（BOOT0 を low に、チップセレクトを high に、リセットを pull-up に）。
  出力（`low` / `high`）の idle を持つピンは、ログの素通しの受け口にはできません。
- **disable を使う場面**: ボードの部品につながったピン（LED、ボタン、起動のストラップ、PSRAM の選択線）、同じ信号を 2 本目に
  つないだピン。disable のピンは起動のときから触られません。
- 機能がピンを使い終えると、ピンは idle の状態（値が無ければ Hi-Z）に戻ります。

## デバッグの線

| 項目 | カテゴリ | key | 値 | 目的 |
|---|---|---|---|---|
| `channel.<SWDIO のピン>.rest` | `oep.wire.rvswd` | 口の SWDIO | `high`、`low` | その口の SWCLK の休ませ方を固定する。値が無ければプローブが相手から選ぶ |
| `channel.<SWDIO のピン>.hold` | 各 wire（`oep.wire.rvswd`、`oep.wire.swio`、`oep.wire.swd`） | 口の SWDIO | 真偽 | 接続を閉じた後も線を駆動したまま保つか。値が無ければ保つ |

- **rest**: CH32L103 は low、CH32X035 は high でないとつながりません。ふつうはプローブの選び方に任せ、決まった相手で固定したいときだけ使います。
- **hold**: 線を放すと、デバッグの状態を数 ms で失う相手（CH32L103）や、誤りの状態に入る相手（CH32V103）があるので、既定では保ちます。
  閉じた後の線を放したい治具だけ false にします。ピンをほかの機能が取れば、保持はそこで終わります。
- 線の種類、速さの上限、止めてつなぐか、リセットをかけながらつなぐかは、接続のたびに道具が渡します（本体設定ではありません）。
  相手ごとの値は [デバッグの対応ターゲット](debug-targets.ja.md) にあります。

## 素通し

セッションの無い間、相手の出力をプローブのシリアルポートへそのまま流す設定です。普通のシリアルモニタで、ログを見られます。
key はプローブのシリアルポートの名前です（`cdc0`、`bridge0`、`usj0` など。`oep dump` の経路の一覧の順）。1 つのポートに置ける素通しは 1 つです。

**UART の素通し**（カテゴリ `oep.fixture.uart`）

| 項目 | 値 | 目的 |
|---|---|---|
| `passthrough.<ポート>.rx` | ピン | 受けるピン（相手の TX につなぐ）。値があれば素通しをする |
| `passthrough.<ポート>.baud` | 数 | 速さ。値が無ければ 115200 |
| `passthrough.<ポート>.format` | `8n1`、`7e2` など | 形式。値が無ければ 8N1 |

**デバッグの線のログの素通し**（カテゴリ `oep.target.console`）

| 項目 | 値 | 目的 |
|---|---|---|
| `passthrough.<ポート>.wire` | `oep.wire.rvswd` か `oep.wire.swio` | 使う線 |
| `passthrough.<ポート>.swdio` | ピン | SWDIO（1 線なら SWIO） |
| `passthrough.<ポート>.swclk` | ピン | SWCLK（2 線だけ） |
| `passthrough.<ポート>.mechanism` | `sdi`、`dmdata`、`dmseq` | 相手がログを出す方式 |
| `passthrough.<ポート>.max-speed` | 数 | 速さの上限。値が無ければプローブが決める |

- 素通しは、ほかの道具がそのポートでプローブを使い始めると止まり、終わると戻ります。素通しのために断られる操作はありません。
- 向きは相手 → PC だけです。相手へ送るには、道具から UART の送信やコンソールの送信を使います。
- デバッグの線の素通しは、相手を止めず、リセットもしません。2 線（RVSWD）の相手は、つなぐときに相手がリセットされることがあるので、
  条件がそろうたびに 1 回だけつなぎに行きます。

## ネットワーク（Wi-Fi のあるプローブ）

| 項目 | カテゴリ | 値 | 目的 |
|---|---|---|---|
| `wifi.<番号>.ssid` | `core` | 文字 | 入るネットワーク。番号の順に試す |
| `wifi.<番号>.passphrase` | `core` | 文字（書くだけ） | パスフレーズ。読み出せない |
| `ipv4.<netif>.mode`、`.address`、`.prefix`、`.gateway`、`.dns` | `core` | アドレスなど | 固定のアドレスにするとき |

- 設定はシリアルポートから行い、保存します。つながったら `oep settings network <プローブ>` でアドレスが分かり、`oep find` で見つかります。
- OEP には認証がありません。信頼できるネットワークでだけ使います。

## メモ欄

設定とは別に、プローブには短い記録を置く場所（`oep.probe.memo`）があります。口の先の相手の型番やメモは
`oep.probe.memo/port/<口>` に置くと、どの PC の道具からも同じ記録を読めます。ラベルが配線の正で、メモは人の読む記録です。
メモの内容でプローブがピンを動かすことはありません。

## firmware が足した項目

自分でビルドした firmware は、独自の項目を足せます（`addSetting`）。`oep settings items` に、ほかの項目と同じ形で出ます。
再起動で効く項目は、items にその印が付きます。

## 用途から引く

| やりたいこと | 本体設定 | 操作の条件 |
|---|---|---|
| CH32 に書き込む・デバッグする | ラベル（`swdio`、`swclk` / `swio`、`nrst`）。必要なら `rest` | 速さの上限、止めるか、リセットするか |
| UART のログを読む | ラベル（`rx`、`tx`）。普通のシリアルモニタで見るなら UART の素通し | baud、形式 |
| デバッグの線でログを読む | ラベル。普通のシリアルモニタで見るならコンソールの素通し | 方式（`dmseq` など） |
| 波形を取る | 無し（ラベルがあれば名前で指せる） | チャネル、速さ、サンプル数、トリガ |
| I2C / SPI で話す、相手の代役になる | 無し（必要ならチップセレクトなどの idle） | アドレス、速さ、mode、返すデータ |
| GPIO、PWM、パルス、アナログ | 待機の状態を決めたいピンの idle | 値、周波数、時間 |
| 治具として据え置く | disable、ラベル、idle、素通し、保存と控え | — |
| Wi-Fi で使う | `wifi.*`、必要なら `ipv4.*` | — |
